# 📌 YouTube Comment Blocker — v1.5.4

Скрипт Tampermonkey, скрывающий комментарии YouTube по каналу на страницах видео и Shorts. Правила handle, UCID и регулярных выражений, настраиваемая автоматизация и локальное хранение.

## Установка и использование

1. Установите [Tampermonkey](https://www.tampermonkey.net/).
2. Откройте ссылку на скрипт ниже или вставьте `ytblockhandlecomments.js` в новый пользовательский скрипт.
3. На странице видео или Shorts нажмите правой кнопкой на handle автора или используйте меню `⋯` для блокировки/разблокировки канала.
4. Откройте меню скрипта в Tampermonkey для управления списком, настройками или языком.

## Возможности

- **Блокировка:** по умолчанию handle, дополнительно пары UCID, независимые регулярные выражения и учёт регистра. Расширяются только действия с авторами комментариев.
- **Комментарии и автоматизация:** скрытие, серая или раскрываемая заглушка; автоматические дизлайки, добавление по выражениям и ключевые слова в тексте, handle или метках закрепления. Повторно используемые узлы обрабатываются заново.
- **Список блокировок:** поиск, фильтры типа/меток, выбор, массовые действия и импорт/экспорт JSON или текста. Совпадения выражений подсчитываются, выбираются и раскрываются постранично без перестроения всего списка.
- **Настройки:** восемь разделов с вертикальными полями: сопоставление, комментарии, автоматизация, пары, ключ API, отображение/тема, журналы/диагностика и сброс. На узком экране меню сверху. Изменения сохраняются автоматически, значения по умолчанию отмечены.
- **Внешний вид:** пять размеров текста/интерфейса и светлая, тёмная, системная, инвертированная, YouTube или своя тема. Синхронизация использует штатное состояние тёмной темы YouTube; цвета меняются только в скрипте.
- **Производительность:** кэширование сопоставлений и ограниченный поиск контейнеров комментариев. По 100 записей на странице; экономный режим — 50, небольшие порции, отложенный поиск и ручные запросы по одному. Пропущенные автоматические запросы не повторяются.
- **Журналы:** отдельно локально и в консоль; уровень, объём, префикс, пояс, ISO/свой формат времени, тест, скачивание, подтверждённая очистка и детализация V0–V5. Секретные значения скрыты; проверки отдельных комментариев не записываются.
- **Состояние:** черновики, поиск, фильтры, выбор, страница и прокрутка сохраняются при навигации и смене языка. SPA-навигация сбрасывает временные наблюдатели; диалоги управляют фокусом клавиатуры.

## Пары UCID

1. Блокировка handle действует сразу. Создание пары при блокировке включено по умолчанию и выполняется асинхронно; ошибка сохраняет блокировки и связи.
2. Создание: **handle → UCID**, с сохранением пары и правила `id`. Обновление: **UCID → текущий handle**, с сохранением UCID и заменой старого handle. При отсутствии UCID используется создание.
3. Для создания, обновления и немедленного связывания отдельно задаются страница, официальный API или страница с резервным API. Странице ключ не нужен, API нужен сохранённый ключ.
4. Для сопоставления UCID включите обнаружение и правила пар. Пока правило не создано, используйте режим handle. Пары по словам следуют политике создания; экономный режим разрешает ручные действия.
5. Выберите интервал или число секунд (не менее одной). По умолчанию: 10 минут для страницы и неделя для API. Общее обновление учитывает интервал, выбранные handle проверяются принудительно.
6. Запускайте операции в списке блокировок. Доступны состояния, результаты по handle, фильтры, сортировка, копирование/экспорт ошибок, прогресс и баннер на странице видео. Проверка ключа помогает при повторных ошибках квоты.
7. По странице читаются метаданные самого канала. API-обновление требует совпадающий UCID и URL вида `@handle`. Отсутствие данных, конфликт, отмена или ошибка сохраняют связи.

## Хранение и конфиденциальность

- `blocked_v2`: правила `handle`, `id` (UCID), `regex`. Формат JSON/текста сохранён, включая `/pattern/flags`.
- `pair_meta_v1`: связи UCID и проверки; `app_settings_v1`: настройки; `youtube_data_api_v3_config`: ключ, тесты и квота; `lang`: язык.
- Пары и ключи исключены из импорта/экспорта списка. Ключ хранится локально и отправляется только в официальный API. Журналы скачиваются с временем UTC ISO; место выбирает браузер.
- Синхронизация использует ревизии и метки удаления, объединяя добавления без восстановления удалённых правил/записей. Ошибка чтения блокирует запись; отказ записи сохраняет прежние данные.
- Старые списки мигрируют только без актуальных валидных данных. UID заменяется на UCID с сохранением ключей, ревизий, удалений и времени. После обновления перезагрузите вкладки со старым скриптом.
- Подробные схемы, токены времени и реализация описаны в Wiki ниже.

## По умолчанию

- Режим handle, полное скрытие, дизлайки выключены, немедленные пары включены. При установке все три политики используют страницы.
- Текст/интерфейс — уровень 3, уровень 2 соответствует прежнему. Диагностика V3; V0/V1 без деталей, V2 — 1 поле, V3 — 3, V4 — 6, V5 — 10.
- Экономный режим и журналы выключены. Ключевые слова без учёта регистра, по умолчанию в тексте; действия выполняются после включения.
- Обновления сохраняют настройки и свои интервалы. Изменение поиска или языка не сбрасывает правила и черновики.

## Ограничения и примечания

- Поиск по странице недокументирован и может сломаться после изменения HTML. API расходует квоту; готовые правила UCID сопоставляются локально. Для проверки ключа используется постоянный публичный канал.
- Старые handle могли быть в нижнем регистре; точный регистр гарантирован после повторного сохранения. Выражения проверяют handle, ключевые слова — выбранные поля.
- Выражения проверяются по длине, флагам и сложности; цель ограничена 128 символами. Обработка только в поддержанных областях видео/Shorts; баннер пар только на видео.
- Ответы YouTube/API, данные пользователя, идентификаторы, поля протокола и машинные журналы не переводятся. Встроенные плееры исключены, используются только перечисленные права.
